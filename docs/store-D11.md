# D11：RunStore——活動資料放哪、怎麼安全地存（2026-11-18）

## 白話
一檔活動的資料是一組檔（狀態、快照、草稿、檢查報告、log、產出的 HTML）。單機版把它們放在一個資料夾，程式到處直接讀寫（`server.js` 有 216 處）。
多人同時用、資料放 S3 之後，這樣會出事：兩個人同時存會互蓋、核可之後內容被改沒人知道、畫面上的舊價格存回來蓋掉新價格。
D11 把「放哪」和「怎麼安全地存」集中到 `core/store` 一處。

## 做了什麼
| 檔 | 內容 |
|---|---|
| `core/store/index.js` | RunStore：建立／列表、狀態檔、log、存草稿、核可、舊版。四條規則寫一份，兩種後端共用 |
| `core/store/fs_backend.js` | 本機資料夾後端。擺法與單機版 `runs/<編號>/` 相同，舊版叫 `draft.vN.json` |
| `core/store/s3_backend.js` | S3 後端。寫入帶 If-Match／If-None-Match；舊版靠 bucket 版本控管 |
| `core/store/memory_s3.js` | 記憶體版 S3，測試用（照 S3 的規則回 412、留舊版） |
| `core/store/fingerprint.js` | 內容指紋：內容相同指紋就相同，跟鍵順序、縮排無關 |
| `core/store/truth_fields.js` | 真值欄照伺服器 |
| `tools/store_s3_check.js` | 拿真的 bucket 驗一次（`npm run store:s3check`） |
| `test/unit/run_store.test.js` | 18 個測試；同一套案例本機資料夾與 S3 各跑一次 |

## 四條規則
1. **舊版存檔 409。** 存草稿要帶「我是從哪一版改的」。伺服器那份已經不是那一版，就回 409 加最新版，不寫入。比對和寫入是同一步，兩個人真的同時按儲存也只有一個成功。
2. **真值欄照伺服器。** 畫面存檔時，商品的品名、價格、劃線價、連結、優惠原文以伺服器為準；畫面送來不同的值會被改回去，並回報改了哪幾欄。系統自己的寫入（建立、價格對真、換品）不受限。
3. **核可綁內容指紋。** 核可時記下當時的指紋。之後內容變了，核可失效（清掉核可時間、留下上次核可時間、寫 log）；內容沒變的存檔不動核可。審核者畫面上若是舊版，按核可會被擋。查「現在算不算已核可」時會再比一次指紋，所以就算有程式繞過存檔流程直接改檔，核可也不算數。
4. **留舊版。** 每次覆寫草稿都拿得回上一版。

## 與單機版的差別
| | 單機版 | RunStore |
|---|---|---|
| 舊版存檔 | 比檔案時間，而且只擋「系統改過之後」的畫面存檔；畫面沒帶時間就放行 | 比內容版本；畫面存檔一定要帶，任何人先存了都擋 |
| 真值欄 | 沒有這條（靠發佈前檢查 CP-02 事後抓） | 存檔當下改回伺服器值 |
| 核可失效 | 任何寫草稿的動作都讓核可失效（13 處各自呼叫） | 內容真的變了才失效，集中一處 |
| 寫草稿的地方 | 18 處各自備份、各自清核可（守門 G3 在數） | 只有 `saveDraft` 一處 |

## 沒做完
- **還沒接上。** `server.js` 仍直接讀寫資料夾；D13 的路由與背景工作改用 RunStore。所以現在單機版的行為完全沒變。
- **沒有對真的 S3 跑過。** 測試用的是記憶體版。真的 bucket 要驗三件記憶體版證明不了的事：支援條件式寫入、版本控管有開、憑證權限夠。`npm run store:s3check` 就是做這件事，等 bucket 下來跑。
- **AWS SDK 還沒加進相依。** `@aws-sdk/client-s3` 用到才載入，本機開發與 CI 不需要。D12 接密鑰管理時一起加。
- 本機資料夾後端只保證同一個程序內不互蓋；多個程序同時寫同一個資料夾不保證（那是 S3 後端的工作）。
- 刪除活動目前是直接刪；單機版的「移到回收區可還原」D13 再搬。
