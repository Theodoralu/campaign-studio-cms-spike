# D13：主流程接到新伺服器（2026-11-19）

## 白話
D12 架了伺服器但只能看列表和核可。D13 把主流程每一步接上去：貼網址建立、編修存檔、檢查、核可、製作 HTML 檔、下載。前面做的零件（D6–D11）到今天才第一次被新伺服器用到。還沒有畫面，全部是 API。

## 路由
全部在 `/api` 底下、都要登入；核可另要審核者身分。網址形狀沿單機版。

| 步驟 | 路由 | 做什麼 |
|---|---|---|
| 建立 | `POST /runs` | 貼網址開一檔；馬上回活動編號，實際工作在背景跑 |
| | `GET /runs/:id/status` | 建立與製作的進度 |
| 編修 | `GET /runs/:id/draft.json` | 讀草稿；回應標頭 `X-Draft-Version` 是這一版的代號 |
| | `PUT /runs/:id/draft.json` | 存草稿；要用 `If-Match` 或 `X-Draft-Base` 帶回那個代號 |
| | `GET /runs/:id/snapshot.json` | 讀來源快照 |
| | `POST /runs/:id/rename` | 改活動名稱 |
| 檢查 | `POST /runs/:id/gate`、`GET …/gate_report.json` | 發佈前檢查（body `{full:true}` 是全檢）與報告 |
| | `POST /runs/:id/product-check`、`GET …/product_check.json` | 商品狀態檢查與報告 |
| 核可 | `POST /runs/:id/approve` | 審核者核可；鎖這一版 |
| 製作 | `POST /runs/:id/export-aem` | 開始製作 HTML 檔（背景） |
| | `GET /runs/:id/export.aem.html` | 下載做好的檔 |
| 舊版 | `GET /runs/:id/versions`、`POST …/versions/:v/rollback` | 舊版清單與還原 |

## 每一步的門
- **建立中、製作中**的活動不收會改資料的請求（409 `busy`）。
- **存草稿**：沒帶版本（`missing-base`）、帶舊版（`stale-draft`，附最新版）都是 409；內容不合規格是 400。
- **核可**：不是審核者 403；看的不是最新版 409 `approve-stale`；這一版還沒跑過檢查 409 `gate-stale`；檢查有必修項目沒過 409 `gate-fail`，要帶 `ackFail: true` 明確表示知悉才收，並留下「帶幾個 FAIL 核可」的印記。
- **製作**：沒核可 409 `not-approved`。製作內部三關沿單機版：商品狀態 → 全檢 → 組檔與顯示檢查，任何一關沒過就不產檔。
- **下載**：還沒做好 409 `not-exported`；做好之後草稿又被改 409 `export-stale`（那份檔已經不是最新內容）。

## 與單機版不同的地方
1. **商品來源是 uther，不爬網頁。** 結果：建立出來的草稿沒有劃線價（uther 沒有這欄）。
2. **售完的商品不進商品池。** uther 快照帶庫存狀態，D8 留了開關，CMS 把它打開。測試時發現不開的話，售完商品會被排上頁面，到製作時才被擋。
3. **建立期價格對真走 uther**（單機版逐件開商品頁，約 30 秒；uther 一次查完）。
4. **存草稿一定要帶版本**（D11 的規則）。
5. **核可前這一版必須跑過檢查。** 單機版由前端把關，新伺服器在後端擋。
6. **策展方式固定是規則版**，狀態檔的 `engine`、`engineUsed` 都是 `rules`。

## 讀程式與測試時發現的
- **主題填錯會讓建立失敗，訊息不準。** 主題跟商品對不上時（測試用零食店配「法式餐廚」），策展回「商品池僅 0 件，來源頁可能不支援解析」。實際是主題把商品全篩掉了。這是單機版原有行為，訊息該改，還沒改。
- **uther 版的頁面比爬頁版大。** 同一家店，爬頁版草稿 32 件商品，uther 版 63 件（池子 120 件）。做出來的 HTML 約 447 KB。

## 沒做完
- **商品頁層的檢查沒接。** 計畫（P40）訂核可與製作前要逐件開商品頁確認（才拿得到劃線價、才是最終真值）。那段判讀程式還在單機版 `server.js` 裡沒抽出來，所以 D13 的商品狀態檢查只有 uther 層。`cms/pipeline.js` 已留好接口（給 `productLiveness` 就自動改走商品頁層）。
- **顯示檢查在這條路上沒有用真 Chrome 跑過。** 測試用假的；真 Chrome 版 `chromeVerify()` 寫好了但只在 CI 的 `aem-verify` job 那條路驗過同一支 `aem_verify.js`。
- **沒有對真的 uther 跑過。** 測試用 D6 錄的卡帶。
- **背景工作跑在伺服器程序裡。** 伺服器重啟，跑到一半的工作就沒了，狀態會停在中間階段。第一版 1 個 replica 可接受。
- **發布**：`publisher` 接口留著、預設不做，等 ECSEARCH-39133 結論。
- **沒搬的路由**（D14 接前端時看實際缺哪些）：換主視覺組合、上傳背景、本期活動重組、編輯精選補件、探索卡修復、內文模組、換品、封存與刪除。核可的「換版式後強制重驗」跟著換主視覺那批。
- 單機版 `server.js` 沒有改，兩個伺服器並存。
