# CMS 文案準則 UX Writing Guide v2

2026-07-27 全面體檢後改版（v1 2026-07-25）。適用：workbench 所有使用者可見文字——按鈕、標籤、placeholder、提示、對話框、錯誤、空狀態、漏斗步驟、chip、合規白話層。
原則來源：Nielsen Norman Group（錯誤訊息）、Google Material、Apple HIG ＋ 台灣繁中電商在地化。
使用者＝電商營運/活動企劃（**不是工程師**）。

> **鐵律：新增或修改任何使用者可見文字前，先過本檔 12 原則與詞彙表。** 合規白話層 gateFriendly、DEPLOY_ZH 等對照層沿用同標準。

## 12 條原則

1. **先講發生什麼，再講怎麼辦**。每則訊息＝白話現況＋一個具體可做的下一步。只有診斷、沒有出路＝不合格。
2. **禁用系統內部詞彙**。程式變數（refreshPolicy）、腳本名（selftest、price_qa）、欄位鍵（gdid、actid、imgs[0]）、檔名（snapshot.json、draft.vN.json）、階段碼（product_check、site_gates、promote）、內部編號（U19、CP-06、R3、N-21、13號平台）、治理術語（真值鎖定、機器閘、站級兩閘、晉升）一律不得出現在 UI。
3. **下一步要能「直接做」**。動作指向畫面上看得到的按鈕/入口名（🔄 替換商品、🩺 商品狀態、→ 前往欄位、⬇ 下載 ZIP），不寫「請重跑／請重新校準」這種抽象建議。
4. **不怪、不嚇使用者**。原始例外（e.message/r.error）絕不當主文，收進句尾「（技術訊息：…）」。避免「中止／失敗／非法／未通過」威嚇字。不硬編個人名，改指向角色（系統管理員）。
5. **台灣繁中在地語彙**。網址（非 URL）、貼上、檔期、賣場、線上/進行中（非「在線」）、編修（非「編輯器」）。短句、主動語態、稱「你」（不用「您」「使用者」）。不夾陸語/英文（Sheet、Picker、在線）。
6. **全站一致：一個概念一個詞、一個真源**。上線（不用 部署/晉升/上線 demo/demo site）、網址、賣場編號、替換商品、編修——各定一詞。顯示文案集中單一真源，避免 DEPLOY_ZH／DEPLOY_CHIP 兩套定義漂移。
7. **漸進揭露：資訊分層**。焦點結論先（L1）→任務細節（L2）→規格/條件/原始輸出收折（L3，`<details>`）。清單超過 3 項或含出現條件就拆短句/分行，不堆成一整段長牆。
8. **正向語氣：講「通過才前進」不講「未過即中止」**。「每一關都通過才會上線；中途沒過會自動停下並告訴你原因，不會動到現有頁面」。
9. **指路用「畫面上的名字」**。用步驟名/按鈕名（「上線 demo 那一步」「下載 ZIP 那一步」），不用「漏斗第 N 步」「chip」等內部結構名，也不硬編步驟數字（會隨改版過期）。
10. **白話層必須全覆蓋，以 code 為鍵 fallback**。gateFriendly/DEPLOY_ZH 要覆蓋所有可能 code；未覆蓋就裸露工程訊息。新增規則碼同步補白話分支（display-only，不動 gate.js/server.js 原始訊息）。
11. **標點與 emoji 節制**。全形「＝」「→」不當賦值符/流程箭頭，改完整中文句（因果用「所以／要重新…」）。emoji 只用於功能辨識，一功能一個（🔄🩺⬇🤖🔒），不堆疊、不放架構口號、狀態列/側欄不常駐威嚇標語。
12. **唯讀/鎖定要講「為何不能改」**。統一「🔒 系統帶入，不可改」，不用工程詞「真值/系統欄」。

## 錯誤訊息公式
```
[✗/⚠] <一句話：發生什麼（使用者視角）>——<現在怎麼做（具體按鈕名，最多兩個選項）>
（可選：一鍵動作）（可選：技術訊息：<原始錯誤>）
```

## 語氣速記
稱「你」；主動、肯定；短句、先結論後細節；因果不用「＝」；技術細節收折；emoji 一功能一個不堆疊；全站一詞一義；不指責/不嚇人/不硬編人名/不夾陸語。

## ⚠ 功能字串護欄（重寫時「只改顯示、勿動判斷值」）

以下字串被程式/測試/gate 依賴，改前必看：

- **建立表單情境下拉（01–05）**：`<option>` 無 value＝可見文字即提交值，存入 `input.scenario`＋retryCreate 回選＋注入 AI 提示。**要改須先補穩定 `value="01"…` 並做既有 run 相容**，勿只改顯示字。
- **人工入稿內容主題／型別下拉**：option value=`promo-activity`/`manual`/`product-fallback`/`activity`/`product`/`search` 驅動邏輯（前後端都讀）——**只改可見文字，勿動 value**。
- **gate.js 原始 msg**（「入口 #\d」「KV 圖 #」「編輯精選圓 #」等）被 gateFieldRef 正則與 gateFriendly `msg.match/includes` 吃——**不可改 gate.js 訊息**；補白話只在 index.html gateFriendly 內「新增以 `f.code` 為鍵的分支」。
- **DEPLOY_ZH/DEPLOY_CHIP/EXPORT_CHIP/PC_CHIP**：物件 key（product_check/site_gates/promote/unverified…）是狀態資料——**只改 value 顯示字，勿改 key**。
- **版本檔名**：`data-rb` 帶 `draft.vN.json`，rollback API 以 `^draft\.v\d+\.json$` 驗證——**只改顯示文字，data-rb 維持檔名**。
- **page.status「待建置」**：是 schema 儲存值（server.js 寫入＋fixtures 用）——**只做顯示映射，勿改儲存值**。
- **missingScopes 兩字串**（「Google 試算表…」「Google 雲端硬碟…」）＋**「系統索引」欄名**：被 `test/unit/*.test.js` 逐字 deepStrictEqual 斷言——**改字要同步改測試與 google_sheets.js/vendor_sheet.js 來源**。
- **nextStepBar 的 act(onclick)**、按鈕 textContent 被 goDeliver 內插——按鈕**顯示字可改**（內插是讀取非比對），但別動 onclick。

> 通則：改任何顯示文案後跑 `bash dod-check.sh static`（67 測試會抓到字面斷言破壞）＋ frametest selftest（模板文案迴歸）。

## 維護
- 新功能的所有可見文字：先過 12 原則＋詞彙表；有白話對照層的（gateFriendly 等）同步補分支。
- 每次文案變更走開發流程（docs/reviews 或 design-qa 記錄，勾「ux-writing 文案」項）。
- 全 CMS 既有文案的分批重寫＝進行中（見 session handoff／重寫優先序）。

## 補充範例：失敗要分「誰的問題」再講（2026-09-24 使用者裁，來源＝離線誠實批）

同一個「讀取沒成功」，先分四種再選句，**責任在誰就講誰**，不要用一句把所有失敗都推給網址：

| 誰的問題 | 結語（檢核表最下面那句） |
|---|---|
| 這台連不到（連線層） | 現在連不到 Yahoo——先確認網路，再按一次「開始策展」；這不是網址的問題 |
| Yahoo 回了但不正常（5xx） | Yahoo 這一次沒回應——請再按一次「開始策展」；連續失敗才需要換來源 |
| 工具本身沒回應 | 工具本身沒有回應——把工具關掉重開，再按一次「開始策展」 |
| 其他沒見過的 | 這一次沒有讀到——請再按一次「開始策展」；一直失敗，把上面的技術訊息交給系統管理員 |
| 真的是網址的問題（前置擋／空殼／零訊號） | 維持：這個網址目前還不能用——照上面的下一步換個來源再試 |

原則：①「不是你的錯」的失敗要明講「不是網址的問題」，否則使用者會一直換網址（2026-09-22 病例：一小時）②技術訊息括號一律印得出原因（`errText()`），空白＝求助無門③安裝階段的「連不到」只提醒不擋（⚠），擋下來會誤傷好電腦。判準與句子的單一真源＝`lib/err_text.js`；前端只選句、不自己判。
